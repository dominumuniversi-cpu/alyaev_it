# AGENTS.md — правила работы с сайтом alyaev.ru

Репозиторий: `E:\!Develop\sites\MY\repo` · прод — **https://alyaev.ru** (корень домена, BASE_PATH пустой).
Стек: Next.js 15 App Router, React 19, TypeScript, Tailwind, FastAPI-бэкенд, PostgreSQL.

## Проверка результата — где смотреть (25.11.2026)

- Редизайн PERSONAL v2.0 проверяется **только на https://alyaev.ru**. Адрес `https://192.168.8.49/alyaev` мёртв (404):
  проверка на нём — это не проверка, а цикл повторов. Один 404 достаточно, второй раз тот же адрес не дёргаем.
- Кириллицу из HTML читать скриптом с явной кодировкой UTF-8 (`WebClient.Encoding = UTF8`),
  не через `curl | Select-String` в PowerShell 5.1: даёт ложное «не найдено».
- Доказательство приёмки: H1, токены, статусы маршрутов, размер портрета, образ контейнера.

## Ограничения для AI-агентов (утверждено владельцем 25.11.2026)

1. **Не создавать новые цвета без согласования.** Палитра PERSONAL v2.0 — бумага `#EAE7DF`, графит `#242522`,
   лайм `#B9E56B`, терракота `#D97859`. Любой новый оттенок — только после явного согласования с владельцем
   и с записью в `docs/manifests/ui/tokens.md`.
2. **Не использовать стандартные шаблоны AI-лендингов.** Никаких «градиентных космосов», стоковых иллюстраций,
   стопок карточек с тенями и glow. Язык сайта — крупная типографика, линии, воздух, инфографика.
3. **Не повторять изображения между услугами.** У каждой услуги уникальный визуал (`PersonalServiceVisual`).
4. **Не генерировать текст внутри изображений.** Подписи, цены и кнопки живут только в разметке: их надо переводить,
   индексировать и читать скринридером.
5. **Не изменять фотографию владельца без отдельного разрешения.** `public/images/about/dmitry-alyaev-about.webp`
   кладётся как есть: без кадрирования, цветокоррекции и перегенерации.
6. **Не создавать фальшивые отзывы и клиентские кейсы.** Демонстрационные проекты помечаются «Демо/концепт».
7. **Не менять SEO URL без согласования.** Структура адресов, canonical, sitemap, robots — трогать только по задаче.
8. **Не переписывать backend ради визуальных изменений.** Редизайн — это фронтенд: стили, компоненты, разметка.
9. **Все новые компоненты должны иметь мобильную версию.** Проверка на 375 / 768 / 1280 px обязательна.
10. **Production не обновлять без тестирования и приёмки.** Сначала сборка и проверка, потом деплой.

## Рабочий процесс (кратко)

- Ветки: `stage/<N>-<тема>` или `feat/<тема>`. Прямые коммиты в `main` — нет.
- Задачи — GitHub Issues; статусы в `TASKS.md` не пишутся.
- Три источника правды: Issues (задачи), kaeru (память/решения), `docs/manifests` (устройство UI и данных).
- Сборка фронта: `docker build -t alyaev-it-frontend:latest --build-arg BASE_PATH= --build-arg SITE_URL=https://alyaev.ru -f frontend/Dockerfile frontend`.
  Проверка — `"basePath": ""` в `/app/.next/routes-manifest.json`.
- Файлы с кириллицей писать только через Node (`fs.writeFileSync(p, text, 'utf8')`), не через PowerShell.
- Не повторять одну и ту же проверку больше двух раз: три одинаковых результата — сигнал сменить действие.
