# Инструкция администратора

Как управлять сайтом, не трогая код. Всё ниже — в админке
`https://alyaev.ru/admin`. Требуется вход с правами администратора.

> Если что-то из описанного не совпадает с экраном — это ошибка в документации
> или в интерфейсе. Правильный экран описан в `docs/manifests/ui/admin-*.md`.

## Начало работы

| Что | Где |
| --- | --- |
| Вход | `/login/` — одна форма для админа и клиента |
| Заявки | `/admin/` |
| Клиенты и доступы | `/admin/clients/` |
| Проекты | `/admin/projects/` |
| Услуги и цены | `/admin/services/` |
| Портфолио | `/admin/portfolio/` |
| Статьи блога | `/admin/articles/` |
| Отзывы | `/admin/reviews/` |
| SEO страниц | `/admin/seo/` |
| Семантическое ядро | `/admin/semantic/` |
| Журнал действий | `/admin/audit/` |

## Заявки

Все обращения с сайта. Приходят с формой, брифом и расчётом калькулятора.

**Статусы:** новая → в работе → квалифицирована → предложение → выиграна / проиграна.
Спам выносится отдельно.

**Что важно знать**

- Уведомления о новых заявках приходят в Telegram. Если плашка в админке говорит,
  что канал не настроен — заявки видно только здесь, проверяйте вручную.
- Блок «Требует внимания» показывает: новые заявки, сообщения клиентов,
  проекты без движения больше недели.
- Ответы брифа видны в карточке заявки. Если он пуст — клиент его не заполнял,
  это нормально, все вопросы необязательные.

## Услуги и цены

Главное правило: **цены живут в базе, а не в коде.** Меняете цену — она меняется
на сайте, в калькуляторе и в разметке сразу после сохранения.

**Как поменять цену:** `/admin/services/` → нужная услуга → поле «Цена от» → сохранить.

**Что обязательно заполнить у услуги** (ТЗ 6.5): начальную цену, срок, что входит,
что не входит, какие данные нужны от заказчика, дополнительные расходы,
гарантийные условия. Пустые поля не выводятся — но и продавать они не помогают.

**Три состояния услуги**

| Поле | Что значит |
| --- | --- |
| `status = published` | Видна на сайте |
| `status = draft` | Черновик, наружу не выходит |
| `price_on_request = true` | Вместо цены «по запросу», в калькулятор не попадает |

## Статьи блога

`/admin/articles/` → новая статья.

**Порядок публикации**

1. Заголовок и текст (Markdown).
2. SEO-поля — Title и Description. **Уникальные.**
3. Статус `published` — только когда статья готова.

> Не публикуйте статьи, обновив только дату. Обновление должно давать что-то новое.
> Это правило ТЗ 11.8, и оно про доверие, а не про поисковики.

## SEO страниц

`/admin/seo/` — блок SEO для каждой страницы: Title, Description, H1, canonical,
Robots index/follow, Open Graph.

**Что проверяет панель:** длину Title и Description, наличие H1, уникальность,
дубли адреса, предпросмотр сниппета.

**Поле Keywords** — только для внутренней работы с семантическим ядром.
Google его не использует. Не тратьте на него время.

## Портфолио

`/admin/portfolio/` — кейсы. У каждого: проблема, архитектура, технологии,
демонстрация, статус.

**Статус честный:** демонстрация / собственный проект / коммерческое внедрение.
Не выдавайте демонстрацию за внедрение — это видно и обходится дороже.

## Отзывы

`/admin/reviews/`. Отзыв виден на сайте только если он `published` **и** получено
согласие на публикацию. Оба условия проверяются на сервере — обойти нельзя.

Пока отзывов нет, страница `/reviews/` отдаёт 404. Это нормально: пустую страницу
наружу не показываем, иначе она мешает и в поиске, и в доверии.

## Клиенты, проекты и доступы

**Порядок:** получили заказ → создали клиента → создали проект →
выдали доступ (`/admin/clients/`, кнопка «Доступ»).

Регистрация в кабинет закрыта намеренно (ТЗ 9.4): клиенты не заводят себе
учётку сами, её создаёт администратор после заказа.

**Клиент видит только свои проекты.** Это проверяется на сервере, а не скрытием кнопок.

## Журнал действий

`/admin/audit/` — кто что менял. Смотрите, если что-то изменилось непонятно откуда.

## Что делать, если

| Симптом | Что проверить |
| --- | --- |
| Заявки не приходят | Плашка про Telegram в `/admin/`, затем `/admin/` — лежат ли они там |
| Цена на сайте не меняется | Сохранена ли услуга, не черновик ли она |
| Страница не находится в поиске | `/admin/seo/`: Robots index, canonical, sitemap |
| Клиент не видит проект | Проект привязан к клиенту? Дано ли право доступа? |
| Статья не видна | Статус `published`? |

## Чего делать не нужно

- Править файлы на сервере руками — есть админка.
- Удалять клиентов и проекты для «чистоты» — есть статусы и архив.
- Заводить дубли услуг под разные запросы. Одна страница закрывает целую группу
  (это правило ТЗ 11.4, и оно про перелинковку тоже).
