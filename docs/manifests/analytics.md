# Манифест: Аналитика и индексация

**ТЗ 11.7:** Яндекс Метрика и Google Analytics 4 — обязательны для целей и конверсий.
**ТЗ 11.5:** sitemap.xml и robots.txt — обязательны.

## Счётчики

| Система | Переменная | Где взять |
|---|---|---|
| Яндекс Метрика | `NEXT_PUBLIC_YM_ID` | metrika.yandex.ru, номер счётчика |
| Google Analytics 4 | `NEXT_PUBLIC_GA_ID` | `G-XXXXXXXXXX` |

**Пустая переменная = счётчик не грузится.** Никаких заглушек и «почти работающих»
счётчиков: скрипт, который ищет несуществующий ID, только замедляет страницу.

### Правило: счётчик не ставится на закрытые страницы

Не грузим Метрику и GA на `/admin`, `/login`, `/account`.
Причина: там работают с чужими персональными данными, а счётчик — это передача
данных третьей стороне. Ограничение по ТЗ 12.6.

## Цели (ТЗ 11.7)

| Событие | Тип | Когда |
|---|---|---|
| `lead_submit` | цель | заявка успешно отправлена |
| `calculator_use` | микроцель | посетитель посчитал стоимость |

Событие отправляется **только после успешного ответа сервера.**
Считать кликом попытку, которая закончилась ошибкой, — значит врать себе в отчётах.

## Sitemap

Что обязано попадать в карту сайта:

| Раздел | Условие |
|---|---|
| Главная, услуги, обо мне, контакты, портфолио, политики | всегда |
| Услуги | все активные |
| **Статьи блога** | **только опубликованные** |
| Кейсы портфолио | только опубликованные |

**Чего в sitemap быть не должно:** кабинет, вход, админка, API, страницы с параметрами.

**Готовые решения** (§7.4) попадают в карту, только если каталог не пуст: пустая страница в индексе — брак.

**`lastmod` берётся из БД, а не из момента сборки:** услуга, кейс и решение — `updated_at`, статья — `published_at`, страница категории — самая свежая правка среди входящих услуг. Карта, где у всех адресов сегодняшнее число, учит поисковика игнорировать это поле.

## AI-краулеры

`GPTBot`, `ClaudeBot`, `PerplexityBot` — полезно разрешать: такие ответы приводят
посетителей, которые уже знают, чего хотят. Разрешаем то же, что и обычным роботам.

## Важно: переменные вшиваются при сборке

`NEXT_PUBLIC_*` попадают в бандл **на этапе сборки образа**, а не читаются в рантайме.
Прописать ID в `E:\DockerData\alyaev-it\.env` недостаточно — нужна **пересборка** frontend:

```powershell
cd E:\!Develop\sites\MY\repo\infra
docker-compose --env-file E:\DockerData\alyaev-it\.env up -d --build --force-recreate --no-deps frontend
```

### Как проверить, что счётчик действительно вшит

**Не искать в HTML страницы.** `Script` со стратегией `afterInteractive` вставляет
тег в браузере — в серверном HTML его нет и быть не должно. Проверять в бандле:

```
docker exec proxy curl -s -k "https://.../alyaev/contacts" | grep -o 'chunks/[^"]*'
# затем в каждом чанке: grep mc.yandex.ru
```

Искать надо **по всем** чанкам страницы: код компонента попадает не в тот чанк,
где его ждёшь, а в один из общих.
