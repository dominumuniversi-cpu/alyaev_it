### Как устроен /services/<slug>/

Один маршрут обслуживает два типа страниц, приоритет — по порядку:

1. **Услуга** (слаг из таблицы `services`): `/services/telegram-bot-for-business` — посадочная с составом, ценами, FAQ.
2. **Категория** (слаг из `service_categories`): `/services/telegram-bots` — список услуг категории.
3. **Алиас из ТЗ**: `ai-assistants`, `knowledge-base` — подгруппы внутри категории `telegram-bots`,
   показывают выбранные услуги. Список алиасов — `TZ_PAGE_ALIASES` в `backend/app/api/public.py`.

Правка списка алиасов без правки этого манифеста — расхождение.

**Пустые разделы не публиковать и не индексировать.** Портфолио и отзывы маркируют демонстрационный статус.

## 2. Авторизация и кабинет

| Раздел | URL | Состояние | Примечание |
|---|---|---|---|
| Вход | `/login/` | **есть** | noindex, защита от перебора |
| Приглашение | `/register/` | **нет, отдаёт 404** | ТЗ 9.4: регистрацию не открываем на первом этапе; учётку создаёт администратор |
| Кабинет | `/account/` | **есть** | noindex; клиент видит только свои проекты (ТЗ 9.1) |
| Вход в кабинет клиента | `/account/login` | **есть** | noindex; отдельная точка входа для клиентов |
| Проект клиента | `/account/projects/[id]` | **есть** | noindex; чужой проект отдаёт 404, а не 403 |

Правило: маршрут, который ещё не реализован, помечается здесь состоянием **«нет, отдаёт 404»**.
Обещать страницу в манифесте и отдавать 404 — расхождение, которое должно быть видно в таблице,
а не обнаруживаться при обходе сайта.

## 4. API

> Внешний API версионируется: префикс **/api/v1**. Next.js переписывает `/api/*` на FastAPI,
> поэтому `/alyaev/api/v1/...` проксируется как есть.

| Группа | Префикс | Доступ |
|---|---|---|
| public | `/api/v1/public/*` | всем |
| leads | `/api/v1/leads` | всем, с rate limit |
| auth | `/api/v1/auth/*` | всем (вход/выход) |
| admin | `/api/v1/admin/*` | персонал |
| account | `/api/v1/account/*` | клиент, только свои данные |
| system | `/api/v1/health`, `/api/v1/ready` | без раскрытия конфигурации |
| seo-admin | `/api/v1/admin/seo/*` | контент-права (редактор) |

**Правило адресов API: без замыкающего слэша.** `trailingSlash: false` в Next превращает
`/api/v1/admin/seo/calculator/` в **308-редирект** ещё до FastAPI — PUT уходит не туда,
и вызов молча «не работает». Пути API всегда пишем без слеша на конце:
`/api/v1/admin/seo/calculator`, а путь страницы передаём в теле или в query.

## 5. Правила

1. Публичный контент доступен в HTML без выполнения JS (SSR).
2. Служебное: кабинет, вход, админка, API — `noindex`.
3. Дублей со слэшем и без быть не должно: canonical всегда один. **Форма адреса — без слэша на конце** (у корня слэша нет вовсе): `canonicalUrl()` в `frontend/src/lib/seo.ts` срезает слэши с обеих сторон пути, иначе канонический адрес сам ведёт на 308-редирект и поисковик тратит на него лишний переход.
4. Изменение URL после публикации — только через 301-редирект.
5. Адреса в `sitemap.xml` — без замыкающего слэша (кроме корня `/`), как и в canonical. Слеш на конце даёт 308 перед 200: карта сайта не должна вести через редирект. Каждый адрес из карты проверяется на живом сайте на 200, а не только на наличие записи.
6. `lastmod` в карте — **настоящая дата правки из БД**, а не дата генерации карты. Услуги, кейсы и решения отдают `updated_at` в публичном API; статья — `published_at`; страница категории берёт самую свежую правку среди входящих в неё услуг. Статическая страница без строки в БД остаётся с датой сборки — это честно, ей нечем оправдать другую. Карта, где у всех адресов сегодняшнее число, учит поисковика не доверять `lastmod` вовсе.

### Страницы контента

| Страница | Адрес | Источник данных |
|---|---|---|
| Портфолио | `/portfolio` | опубликованные кейсы; если база пуста — встроенный демонстрационный набор |
| Статья | `/blog/<slug>` | опубликованная статья; черновик и удалённая → **404** |
| Готовые решения | `/solutions` | опубликованные модули; пустой каталог → блок отсутствует, раздел не в sitemap |
| Решение | `/solutions/<slug>` | опубликованный модуль; черновик и удалённый → **404** |
| Услуга | `/services/<slug>` | посадочная одной услуги (состав, цены, FAQ) |
| Кейс | `/portfolio/<slug>` | опубликованный кейс |

**Перелинковка (ТЗ 11.10):** три вида связей, все ручные, без автоподбора по словам:

| Откуда | Куда | Где хранится | Блок |
|---|---|---|---|
| Услуга | модули | `solutions.service_slug` | «Готовые решения по этой теме» |
| Статья | услуги | `article_services` | «Услуги по теме статьи» |
| Статья | статьи | `article_articles` | «Читайте также» |

Блок не рендерится, если связей нет — ни заголовком, ни пустой сеткой.

**Правило пустого раздела:** пустой список не показываем пустым блоком (ТЗ 16: «нет пустых
блоков и заглушек»). Либо честный текст о том, что раздел в работе, либо встроенный набор
демонстраций. Заглушек вида «скоро здесь будет…» не делаем.
