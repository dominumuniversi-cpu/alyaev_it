# Манифест: Таблица заявок (LeadsTable)

**ТЗ 9.2, 14 (CRM заявок).** Главный рабочий экран владельца: всё, что пришло с сайта.

## Колонки

| Колонка | Источник | Обязательна |
|---|---|---|
| Дата | `leads.created_at` | да |
| Имя | `leads.name` | да |
| Контакт | `leads.contact_type` + `contact_value` | да |
| Тип задачи | `leads.task_type` | нет |
| Источник | `leads.source_page` | нет |
| Статус | `leads.status` | да |

## Статусы заявки

`new` → `in_progress` → `done` → (архив). Удаление — только мягкое (`deleted_at`).

## Правила

- **Пустой список — не пустая таблица.** Показать текст «Заявок пока нет» и что сделать,
  чтобы они появились. Пустой блок без объяснения — дефект по ТЗ 16.
- Новые заявки сверху (`created_at desc`). Владельцу важно видеть свежее первым.
- Контакт показывается **типом**: Telegram — ссылка `t.me`, телефон — `tel:`, email — `mailto:`.
  Кликабельный контакт экономит время; мёртвый текст заставляет копировать руками.
- IP и `user_agent` в списке **не показываем** — это служебные данные, они в карточке заявки.

## Безопасность

- Данные заявок — персональные. Доступ только роли `admin`/`manager` (см.
  `docs/manifests/access-control.md`). Проверка **на сервере**; скрытие кнопок в UI — не защита.
- Экспорт заявок делать осознанно: выгрузка в CSV — это копия персональных данных вне системы.

## Чего не делаем

- Автоматическая рассылка по заявкам из интерфейса.
- Оценка «качества лида» без данных — придуманная аналитика хуже отсутствующей.
