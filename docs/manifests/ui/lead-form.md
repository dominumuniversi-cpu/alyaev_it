## Зачем бриф вместо «имя и телефон» (ТЗ 14)

Заявка «Имя + телефон» заставляет переспрашивать всё на созвоне. Бриф собирает контекст
заранее: что за задача, что сейчас используется, какой результат нужен. Владелец отвечает
уже подготовленным, а клиент не тратит время на повторное объяснение.

## Поля

| Поле | Обязательное | Правило |
|---|---|---|
| Имя | да | минимум 2 символа |
| Контакт | да | Telegram / телефон / e-mail, минимум 3 символа |
| Тип задачи | нет | выпадающий список из услуг |
| Описание задачи | да | минимум 20 символов |
| Сайт компании | нет | только `http://` или `https://` |
| Согласие | да | без него отправка невозможна |
| Honeypot | — | скрытое поле, у человека пусто |

## Передача расчёта калькулятора

Кнопка «Обсудить этот проект» на калькуляторе ведёт на
`/contacts/#lead?source=calculator&service=<slug>&price=<сумма>&options=<через запятую>`.

**Правило:** форма читает эти параметры и показывает клиенту то, что он насчитал,
чтобы он не сомневался, что расчёт дошёл. Дописано в поле описания автоматически —
клиент может отредактировать или стереть.

Формат дописки в сообщении:

```
Расчёт с калькулятора: <название услуги>, опции: <список>, предварительно <сумма> ₽.
```

**Источник заявки** (calculator / page) сохраняется в `source_page`, чтобы в админке было
видно, откуда пришёл лид: с калькулятора или со страницы контактов.

## Онлайн-бриф: уточняющие вопросы (ТЗ 14)

Под полем «Сайт компании», в сворачиваемом блоке «Уточнить детали (необязательно)».
Свёрнут по умолчанию: бриф помогает, но не должен мешать отправить заявку.

| Ключ | Вопрос | Варианты |
| --- | --- | --- |
| `current` | Что используется сейчас | Excel и таблицы / Сайт и почта / CRM / 1С / Другое / Пока ничего |
| `systems` | Какие системы нужно связать | Не нужно / CRM / 1С / Telegram / Google Sheets / Сайт / Другое |
| `result` | Какой результат ожидается | Меньше ручной работы / Быстрее отвечать клиентам / Автоматические отчёты / Поиск по документам / Другое |
| `staff` | Сколько сотрудников задействовано | 1 / 2–5 / 6–20 / больше 20 |
| `tech_task` | Есть ли техническое задание | Есть / В работе / Нет |
| `budget` | Бюджет | до 25 000 ₽ / 25 000–50 000 ₽ / 50 000–150 000 ₽ / больше 150 000 ₽ / Не определён |

**Все поля необязательные.** Обязательных вопросов в брифе нет — требование их закрывает
конверсию, а смысл брифа в том, чтобы помочь клиенту, а не отсеять его.

**Правила**

- ключи брифа совпадают с `BRIEF_FIELDS` на сервере; несовпадение = ответ молча потерян;
- пустые ответы не отправляются и не сохраняются;
- неизвестный ключ сервер отбрасывает, но заявку не отклоняет;
- ответы хранятся в `leads.brief_json` (JSON, а не колонки — вопросы меняются чаще схемы).

## Состояния формы

| Состояние | Что видит клиент |
|---|---|
| idle | поля формы |
| sending | поля неактивны, кнопка «Отправляем…» |
| sent | «Заявка отправлена» + кнопка «Отправить ещё одну» |
| error | текст ошибки под полями, введённое сохранено |

**Правило:** страница не перезагружается (fetch, не `<form method=post>`). Введённые данные
при ошибке не теряются.

## Чего форма не делает

- Не отправляет заявку без согласия.
- Не теряет введённое при сетевой ошибке.
- Не обещает срок ответа, которого нет.
