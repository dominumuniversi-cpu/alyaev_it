# Манифест: Личный кабинет клиента (AccountShell)

**ТЗ 9.1, 9.3, 11.5.** Компонент: `src/components/account/AccountShell.tsx`.
Страницы: `/account` (список), `/account/projects/[id]` (карточка).

## Ключевое правило

Данные приходят **только по cookie сессии**, поэтому кабинет рендерится на клиенте.
Серверный рендер увидел бы пустой кабинет и показал бы «проектов нет» даже тем, у кого они есть.

Изоляция проектов при этом **на сервере** (`app/api/account.py`), компонент только отображает.
Скрытие элементов здесь ничего не защищает и защитой не считается (ТЗ 9.3).

## Состояния

| Состояние | Когда | Что видит клиент |
|---|---|---|
| `loading` | запрос в пути | «Загружаем…» |
| `unauth` | 401, или 404 с чужим/несуществующим проектом | «Нужен вход» + кнопка «Войти» |
| `nocabinet` | 404 с текстом «не заведён» | «Кабинет ещё не заведён» + просьба написать исполнителю |
| `ok` | данные получены | список проектов или карточка |

**Почему 404 делятся на два вида.** Сервер отвечает 404 и когда нет карточки клиента,
и когда проект чужой. Разворачиваем только первый случай — по тексту ответа.
Второй намеренно неотличим от «не существует»: иначе перебором можно узнать, что проект есть.

## Список проектов

| Элемент | Правила |
|---|---|
| Карточка проекта | вся кликабельна, ведёт на `/account/projects/<id>` |
| Название | как в базе, не обрезается |
| Статус | плашка: голубая `new`, золотая `analysis/dev/testing`, серая `done` |
| Стоимость | `12 000 ₽`; при `NULL` — **«по договорённости»**, не «0 ₽» |
| Срок | `24.11.2026`; при `NULL` — прочерк |

Пустой список — честная строка «Проектов пока нет», а не заглушка и не пустая сетка.

## Карточка проекта

Три блока по порядку: **описание и цифры → задачи → история**.

- Задачи: невыполненные выше выполненных, выполненные помечены `✓`.
- История: дата + статус + комментарий, в хронологическом порядке.
- Пустые блоки пишут «Задач пока нет» / «Изменений пока не было», а не исчезают.

## Документы и переписка

Два блока **после истории**: документы, затем переписка.

**Документы.** Список: название, категория, имя файла, размер.
Клик по названию — скачивание. Ссылка ведёт на `/api/v1/account/projects/{id}/documents/{id}`,
сервер сам проверяет, что файл принадлежит проекту клиента.
Пусто — «Документов пока нет», а не пустое место.
**Загрузка клиентом.** Под списком — «Прикрепить документ»: выбор файла + категория +
название (можно не заполнять — возьмётся имя файла) + кнопка «Загрузить».

| Элемент | Правила |
|---|---|
| Выбор файла | `pdf`, `docx`, `xlsx`, `zip`; до 20 МБ. Тот же `check_upload`, что в админке |
| Категория | ТЗ / Акт / Инструкция / Другое — совпадает с `ck_documents_category` |
| Кнопка «Загрузить» | `POST /api/v1/account/projects/{id}/documents` (multipart) |
| После успеха | список обновляется, файл виден сразу, страница не перезагружается |
| Ошибка | текст от сервера над формой, форма не очищается |

Сервер проверяет владение проектом (`_own_project`) — чужой проект не примет загрузку,
даже если подставить id вручную. Право `CONTENT_WRITE` здесь не годится: оно админское.

**Переписка.** Сообщения в хронологическом порядке: свои справа, ответы студии слева.
Под каждым — дата. Поле ввода + кнопка «Отправить»; после отправки поле очищается,
новое сообщение появляется сразу, без перезагрузки страницы.
Пусто — «Сообщений пока нет».

Роль автора приходит с сервера (`author_role`), интерфейс её только отображает.
Клиент видит только `client` и `staff` — другой роли быть не может (проверка на сервере).

## Уведомления

Блок на главной странице кабинета, **над списком проектов** — чтобы ответ не
терялся под списком.

| Элемент | Поведение |
| --- | --- |
| Счётчик | «Непрочитанных: N»; при нуле блок пишет «Уведомлений пока нет» |
| Список | заголовок, текст, дата; непрочитанные выделены |
| «Отметить прочитанным» | на каждом непрочитанном; после нажатия блок меняется без перезагрузки |

Счётчик считается на сервере и приходит вместе со списком:
считать непрочитанные на клиенте по загруженным 50 записям нельзя —
пропущенное уведомление выглядело бы прочитанным.

## Обязательные правила

- `robots: { index: false, follow: false }` на всех страницах кабинета (ТЗ 11.5).
- Кнопка «Выйти» есть на обеих страницах: из карточки не должно быть ловушки.
- При сбое сети при выходе всё равно уводим на вход: показать кабинет после «выхода» хуже.
- Цена `NULL` ≠ ноль. «По договорённости» и «бесплатно» — разные вещи.
