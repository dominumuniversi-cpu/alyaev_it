# Манифест: Портфолио и статьи

**ТЗ 5 блок 6, 11.6, 12.3:** кейсы и статьи ведутся из админки, статус кейса честно указан,
soft-delete вместо физического удаления.

## Портфолио

| Поле | Обязательное | Правило |
|---|---|---|
| `slug` | да | уникален, латиница, дефисы |
| `title` | да | ≤ 200 |
| `summary` | да | ≤ 320 — что за проблема решалась |
| `problem` / `solution` | да | текст, markdown |
| `technologies` | да | список строк |
| `status` | да | `demo` / `own` / `commercial` |
| `published` | да | черновик/опубликовано |

### Статус кейса — обязателен и честен

| Статус | Показывается как | Когда ставить |
|---|---|---|
| `demo` | «Демонстрационный проект» | свой образец, не внедрение у клиента |
| `own` | «Собственная разработка» | внутренний проект |
| `commercial` | «Коммерческое внедрение» | был реальный заказчик |

**Запрещено (ТЗ 5 блок 6):** указывать вымышленную экономию, проценты эффективности,
число клиентов. Поля для таких цифр в схеме есть только на будущее и заполняются
после реальных измерений — на публике пустые поля не показываются.

## Статьи

| Поле | Правило |
|---|---|
| `slug` | уникален |
| `title` | ≤ 200 |
| `excerpt` | ≤ 320, для списка блога |
| `body_md` | markdown, ≤ 100 000 |
| `status` | `draft` / `published` / `archived` |
| `published_at` | ставится автоматически при первой публикации |

**Правило даты:** повторное сохранение опубликованной статьи **не меняет** `published_at`.
Обновление ради «свежей даты» обесценивает блог и вводит читателя в заблуждение.

## Soft-delete

Удаление ставит `deleted_at`, запись остаётся в базе и исчезает с сайта.
Физическое удаление — только администратором и только через базу, не из интерфейса.
Причина: случайно удалённую статью можно вернуть, удалённую физически — нет.

## Публикация

Сайт показывает только `published` и `deleted_at IS NULL`. Черновик виден по прямому
адресу только после входа с правом `content:read`.
