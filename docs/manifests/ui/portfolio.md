# Манифест: Портфолио (`/portfolio/`, `/portfolio/<slug>/`)

**ТЗ 5 блок 6, 11.5, 16.** Пока коммерческих кейсов нет — показываем демонстрационные
проекты и честно называем их демонстрационными.

## Правило источника данных

```
кейсы из БД (published) → если пусто → встроенный набор FALLBACK_PROJECTS
```

**Страница никогда не пустая.** Пустое портфолио — нарушение ТЗ 16 («нет пустых блоков»),
поэтому при отсутствии опубликованных кейсов показывается демонстрационный набор.

> Отличие от `/reviews/`: там при пустоте отдаётся 404 (ТЗ 11.5 прямо требует
> «не индексировать пустые страницы отзывов»). Портфолио — обязательный раздел ТЗ 4,
> поэтому его не скрываем, а наполняем демонстрациями.

## Карточка кейса

| Элемент | Обязателен | Правила |
|---|---|---|
| Статус (`Badge` `variant="status"`) | да | демонстрация / собственный / внедрение |
| Название (ссылка) | да | ведёт на `/portfolio/<slug>` — **без замыкающего слеша** (правило сайта; со слешем 308-редирект, чтобы не было дублей) |
| Описание проблемы и решения | да | 1–2 предложения |
| Технологии (`Badge` `variant="tech"`) | да | 2–4 штуки |
| Ссылка «Как устроено решение →» | да | тот же адрес, второй вход в кейс для явности |

## Правила содержания

1. **Статус честный.** Демонстрация не выдаётся за коммерческое внедрение.
2. **Никаких процентов экономии**, пока не измерены. ТЗ 5: «не придумывать экономию
   денег или проценты эффективности».
3. Каждый кейс отвечает: какая проблема, как устроено, что использовано.
4. Картинка в карточке — с 25.11.2026 всегда: `imageForPortfolio(index)` из
   `frontend/src/lib/design/images.ts` чередует три иллюстрации, чтобы две соседние не повторялись.
   Пропорции из реестра (299×175, 315×175, 328×175), `h-auto`, без `priority`.
5. Иллюстрации — **не скриншоты клиентов**. Бейдж «Демонстрационный проект» (`PORTFOLIO_STATUS_LABELS`)
   остаётся над содержимым карточки и не убирается; выдавать картинку за реальный кейс запрещено.
