# Манифест: Портфолио (`/portfolio/`, `/portfolio/<slug>/`)

---

> **Дизайн-система: PERSONAL v2.0 (25.11.2026).** Цвета и типографика — по `tokens.md`:
> бумага `--c-paper` #EAE7DF, графит `--c-ink` #242522, лайм `--c-lime` #B9E56B,
> терракота `--c-terracotta` #D97859. Где ниже упомянуты старые токены (`--c-gold`, `--c-cyan`,
> `--c-bg`, `--c-surface`, …) — они сохранены как алиасы на новую палитру (см. `tokens.md`, раздел «Совместимость»).
> Радиусы скруглений 0 (кроме полей ввода), декоративные растровые фоны секций отменены.
> С 26.11.2026 в карточках чередуются два вида: **SVG-схема решения** (нечётные карточки) и **растровая
> иллюстрация из пакета** (чётные, `imageForPortfolio`). Владелец попросил «что-то помимо кружочков» —
> поэтому картинки возвращены осознанно, а не случайно.
> Правило разнообразия: **соседние карточки никогда не показывают одно и то же**; пул иллюстраций —
> `portfolioDashboard`, `portfolioGrowth`, `automation`, и в нём нет картинок чужого «рабочего места»,
> чтобы не выдавать их за кейс клиента. Дефект на странице = повтор подряд, а не сам растр.

**ТЗ 5 блок 6, 11.5, 16.** Пока коммерческих кейсов нет — показываем демонстрационные
проекты и честно называем их демонстрационными.

## Правило источника данных

```
кейсы из БД (published) → если пусто → встроенный набор FALLBACK_PROJECTS
```

**Страница никогда не пустая.** Пустое портфолио — нарушение ТЗ 16 («нет пустых блоков»),
поэтому при отсутствии опубликованных кейсов показывается демонстрационный набор.

> Отличие от `/reviews/`: там при пустоте отдаётся 404 (ТЗ 11.5 прямо требует
> «не индексировать пустые страницы отзывов»). Портфолио — обязательный раздел ТЗ 4,
> поэтому его не скрываем, а наполняем демонстрациями.

## Карточка кейса

| Элемент | Обязателен | Правила |
|---|---|---|
| Статус (`Badge` `variant="status"`) | да | демонстрация / собственный / внедрение |
| Название (ссылка) | да | ведёт на `/portfolio/<slug>` — **без замыкающего слеша** (правило сайта; со слешем 308-редирект, чтобы не было дублей) |
| Описание проблемы и решения | да | 1–2 предложения |
| Технологии (`Badge` `variant="tech"`) | да | 2–4 штуки |
| Ссылка «Как устроено решение →» | да | тот же адрес, второй вход в кейс для явности |

## Правила содержания

1. **Статус честный.** Демонстрация не выдаётся за коммерческое внедрение.
2. **Никаких процентов экономии**, пока не измерены. ТЗ 5: «не придумывать экономию
   денег или проценты эффективности».
3. Каждый кейс отвечает: какая проблема, как устроено, что использовано.
4. Схема в карточке — с 26.11.2026 компонент `PortfolioVisual` (`frontend/src/components/site/PortfolioVisual.tsx`).
   Сюжет выбирает `portfolioVisualFor(slug)` из `frontend/src/lib/design/portfolio.ts`:
   `dialog` (Telegram AI-консультант), `search` (AI-поиск по документам), `pipeline` (автоматизация заявок),
   `extract` (парсер данных), `sync` (интеграция с 1С), `digest` (AI-дайджест), `generic` (новый кейс из админки).
   **Две одинаковые схемы на странице — дефект.** Новая сюжетная линия = новый ключ в карте и новая сцена.
5. Схемы — **не скриншоты клиентов**. Бейдж «Демонстрационный проект` (`PORTFOLIO_STATUS_LABELS`)
   остаётся над содержимым карточки и не убирается; выдавать картинку за реальный кейс запрещено.

## Сетка и оформление

| Элемент | Значение |
|---|---|
| Сетка | `grid gap-px` на фоне `--c-line` = разделители линиями, а не «плитки в отступах»; 1 колонка на мобиле, 2 на `sm` |
| Карточка | `bg-[color:var(--c-paper-2)] p-6`, радиус 0 |
| Номер кейса | `01 / PROJECT` моно-шрифтом, `tracking-[0.22em]` |
| Заголовок | display-шрифт, капс, `text-xl`, ссылка → терракота при наведении |
| Замыкающая плашка | `border-t` + призыв и `ButtonLink` (одна основная кнопка на вид) |
