# Каркас админки — общий манифест

> Обязателен для **любой** страницы `/admin/*`. Перед новой страницей админки читается
> вместе с `docs/manifests/access-control.md` и `docs/manifests/ui/tokens.md`.
> Ссылка на этот файл уже стоит в `AdminNav.tsx` и в `admin-content.md` — раньше она вела в никуда.

## Зачем общий каркас

Админка — рабочее место, а не витрина. Администратор ходит по разделам десятки раз в день.
Каждый раздел обязан открываться одинаково: одно и то же место заголовка, одно и то же меню,
одни и те же отступы. Иначе переключение между разделами каждый раз требует заново
ориентироваться, и человек ошибается.

## Устройство страницы

Все страницы админки живут под путём `/admin/` (с `BASE_PATH`, у нас `/alyaev`):

| Раздел | Путь | Данные |
|---|---|---|
| Заявки | `/admin/` | `leads` |
| Услуги и цены | `/admin/services/` | `services` |
| Портфолио | `/admin/portfolio/` | `portfolio` |
| Блог | `/admin/articles/` | `articles` |
| Отзывы | `/admin/reviews/` | `reviews` |
| Семантика | `/admin/semantic/` | `semantic_queries` |
| SEO | `/admin/seo/` | `seo_metadata` |
| Журнал | `/admin/audit/` | `audit_log` (только чтение) |

Порядок в меню фиксирован и задаётся в `components/admin/AdminNav.tsx` — он отражает частоту
работы: заявки открывают каждый день, журнал — когда что-то пошло не так.

## Обязательная разметка

```tsx
<main className="mx-auto w-full max-w-[1200px] px-4 py-10 sm:px-6 lg:px-8">
  <AdminNav current="/admin/статьи/" />   // путь С ЗАМЫКАЮЩИМ СЛЕШЕМ
  <div className="mb-6 flex flex-wrap items-center justify-between gap-3">
    <h1 className="text-2xl font-semibold">Раздел</h1>
  </div>
  {/* содержимое раздела */}
</main>
```

Правила:

1. **Ровно один `h1`** на странице, он же название раздела в меню.
2. **`AdminNav` идёт первым** после `<main>`, до заголовка: меню — самая частая точка перехода.
3. **`current` совпадает с `href` из `SECTIONS` дословно**, включая замыкающий слеш.
   Не совпало — подсветка активного раздела молча пропадёт, и человек не поймёт, где он.
4. **Ширина `max-w-[1200px]`** и те же отступы на всех разделах. Таблица заявок и редактор
   статей должны стоять на одной оси.
5. Цвета — только через переменные темы (`var(--c-gold)`, `var(--c-text)` и т.д.),
   см. `tokens.md`. Захардкоженный цвет — расхождение с дизайн-системой.

## Индексация: всегда закрыта

Каждая страница админки объявляет метаданные явно:

```tsx
export const metadata: Metadata = {
  title: "Заявки",
  robots: { index: false, follow: false },
};
```

Это не подстраховка, а требование ТЗ 11.5. Плюс страховка на уровне `robots.txt`.
Проверка: `curl -s https://…/alyaev/admin/ | grep -o 'noindex'` должен что-то найти.

## Доступ проверяется на сервере

Скрытый пункт меню доступа не закрывает. Права проверяются в backend на каждом запросе
(`docs/manifests/access-control.md`); UI без права — это удобство, а не защита.
Отдельная защита входа (лимит попыток) описана там же.

## Данные грузятся на клиенте

Страницы админки — клиентские таблицы (`LeadsTable`, `ServicesEditor` и т.п.). Данные приходят
с cookie сессии, поэтому серверный рендер их не получит. Отсюда следствие для оформления:
**состояние загрузки и пустоты обязательны.** Пустая таблица без пояснения неотличима
от сломанной — администратор не поймёт, кончились заявки или упал запрос.

## Чего не делаем

- Не заводим второй каркас «для одной страницы» — расходится и разъедется.
- Не выводим в админке публичную шапку и подвал сайта.
- Не показываем в меню разделы, которых ещё нет: кнопка в никуда хуже её отсутствия.
- Не делаем действия, перезагружающие страницу (см. RULES.md, правило о действиях пользователя).

## Как проверить новую страницу

1. Открыть раздел и соседний — заголовок, меню и ширина стоят на месте.
2. Активный пункт меню подсвечен.
3. В исходнике есть `noindex`.
4. Пустой список и ошибка загрузки выглядят по-разному и оба понятны.
