## Зачем

Администратор может поменять цену, удалить статью или отзыв. Без журнала невозможно
ответить на вопрос «кто это сделал» — ни при разборе ошибки, ни при споре с клиентом.

## Что фиксируется

| Поле | Смысл | Правило |
|---|---|---|
| `actor_user_id` | кто | `NULL` = система (фоновая задача) |
| `action` | что | `сущность.глагол`: `service.update`, `article.delete` |
| `entity` | тип объекта | короткое имя таблицы: `service`, `article`, `review` |
| `entity_id` | какой объект | строка, чтобы не зависеть от типа ключа |
| `payload` | что изменилось | только изменения, без секретов |
| `created_at` | когда | ставится БД |

## Три правила, которые нельзя нарушать

**1. Запись в той же транзакции, что и изменение.** `audit.record()` только добавляет
строку в сессию, коммит делает вызывающий код. Если коммитить внутри помощника, при
ошибке дальше в коде в журнале останется след о действии, которого не случилось.

**2. В payload — только изменения, а не снимок объекта.** `diff()` возвращает
`{поле: {"было": ..., "стало": ...}}`. Двадцать одинаковых полей прячут суть: ревьюер
должен видеть одну поменявшуюся цену, а не весь объект.

**3. Секреты не попадают в журнал никогда.** `_sanitize()` заменяет значения полей
`password`, `token`, `secret`, `api_key` и подобных на `[скрыто]`, оставляя факт
изменения. Проверка регистронезависимая и работает во вложенных словарях.

## Покрытие — проверяется тестом

Каждый изменяющий маршрут в `app/api/admin_*.py` обязан писать в журнал.
Тест `test_sensitive_actions_are_logged` сравнивает число маршрутов
(`@router.post|patch|put|delete`) с числом вызовов `audit.record()` и падает при
расхождении. Добавили маршрут, забыли журнал — сборка красная.

## Чтение

`GET /api/v1/admin/audit` — требует право `audit:read` (есть у админа и менеджера,
нет у редактора и клиента). Фильтр по `entity`, пагинация `limit`/`offset`,
новые записи сверху. Имена авторов подтягиваются одним запросом, а не по строке.

## Что НЕ пишем

Запись журнала не редактируется и не удаляется из интерфейса — иначе журнал теряет смысл.
Чтения (`GET`) не логируются: журнал про изменения, а не про просмотры.
