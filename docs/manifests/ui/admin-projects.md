# Манифест: страница админки «Проекты» (`/admin/projects/`)

> Источник требований: ТЗ §9.2 (кабинет администратора), §9.1 (что видит клиент).
> Смежные манифесты: `ui/admin-layout.md`, `ui/field.md`, `ui/button.md`, `ui/badge.md`,
> `ui/admin-clients.md`, `db/schema.md`.

## Назначение

Ведение проектов клиентов: создание, смена статуса, добавление задач.
Всё, что здесь меняется, клиент видит в своём кабинете.

## Компоновка

| Порядок | Блок | Обязательность |
| --- | --- | --- |
| 1 | `AdminNav` с `current="/admin/projects/"` | всегда |
| 2 | `h1` «Проекты клиентов» | всегда |
| 3 | Пояснение под `h1` | всегда |
| 4 | Строка уведомления (`role="status"`) | только после действия |
| 5 | Карточка «Новый проект» | всегда |
| 6 | Список проектов | при наличии проектов |
| 7 | Пустое состояние | при нуле проектов |

`max-w-[1200px]`, `robots: { index: false, follow: false }` — как у всех админских страниц.

## Форма «Новый проект»

| Элемент | Тип | Имя поля | Обязательность | Правило |
| --- | --- | --- | --- | --- |
| Клиент | `SelectField` | `client_id` | да | список из `/admin/clients` |
| Название проекта | `TextField` | `title` | да | максимум 200 символов |
| Стоимость, ₽ | `TextField type="number"` | `price_rub` | нет | не меньше 0 |
| Описание | `TextAreaField` | `description` | нет | 3 строки |
| Создать проект | `Button type="submit"` | — | — | `fetch`, без перезагрузки |

**Пустая стоимость отправляется как `null`, а не `0`.** Ноль — это конкретная цена,
а не «не задана». В базе `price_rub` допускает `NULL`; на витрине такой проект
показывается как «по договорённости».

**Если клиентов нет**, форма заменяется подсказкой: «Сначала создайте клиента
в разделе «Клиенты». Проект без клиента не заводится.» Кнопка не показывается —
чтобы не вести в тупик.

## Список проектов

Каждый проект — отдельная карточка:

| Элемент | Содержимое |
| --- | --- |
| Название | `title` |
| Подпись | имя клиента · цена |
| Бейдж статуса | `Badge variant="tech"` |
| Выбор статуса | `select` с пятью значениями |
| «Добавить задачу» | раскрывает поле, повторное нажатие сворачивает |

### Статусы

| Код | Подпись |
| --- | --- |
| `new` | Новый |
| `analysis` | Анализ |
| `dev` | Разработка |
| `testing` | Тестирование |
| `done` | Завершён |

Слова **совпадают** с подписями в кабинете клиента: один статус не должен называться
по-разному на двух экранах.

Неизвестный код статуса показывается как есть, а не скрывается: лучше увидеть
непонятное значение, чем пустое место.

### Смена статуса

Выбор в списке сразу отправляет `PATCH /admin/projects/{id}/status`.

- Никакой кнопки «Сохранить»: одно действие — один жест.
- Список обновляется точечно после успеха, страница не перезагружается.
- Пока запрос идёт, `select` заблокирован.
- Сервер пишет событие в историю проекта; повтор того же статуса историю не засоряет.

### Добавление задачи

Кнопка «Добавить задачу» раскрывает поле **внутри карточки** проекта.
Отправка — `fetch`, поле очищается, блок сворачивается.

## Состояния экрана

| Состояние | Что видно |
| --- | --- |
| `loading` | «Загружаем…» |
| `error` | «Не удалось загрузить проекты» (`role="alert"`) |
| 401 / 403 | переход на `/login/` |
| нет клиентов | подсказка вместо формы |
| нет проектов | «Проектов пока нет.» |

Загрузка идёт двумя запросами параллельно (`Promise.all`): проекты и клиенты.
Если хоть один ответил 401/403 — переход на вход.

## Доступ

Все действия — право `projects:all`. Проверка на сервере.

## Журнал действий

| Действие | Запись |
| --- | --- |
| создание проекта | `project.create` |
| смена статуса | `project.status` |
| добавление задачи | `project.task_create` |

## Связанные API

- `GET /api/v1/admin/projects`
- `POST /api/v1/admin/projects`
- `PATCH /api/v1/admin/projects/{id}/status`
- `POST /api/v1/admin/projects/{id}/tasks`
- `GET /api/v1/admin/clients` — для выбора клиента

## Что осталось

- Задачи пока только создаются; смена их статуса и удаление — через API.
- Срок выполнения (`due_at`) и история статусов пока не показываются на экране.
