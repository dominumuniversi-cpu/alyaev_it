# Манифест: Бесплатный разбор процесса (диагностика)

**Страница:** `/diagnostics/`. **Файл:** `frontend/src/app/diagnostics/page.tsx`.
**Основание:** ТЗ 7.2.

## Главное правило

> Это **не** бесплатная разработка и **не** консультация на час.
> Это разбор одного процесса: посмотреть, как он идёт сейчас, показать, где теряется время,
> и честно сказать — стоит ли его автоматизировать и с чего начать.

Страница должна продавать не «бесплатно», а **результат разбора**. Иначе приходят за халявой.

## Что обещаем (и что получит клиент)

| Обещание | Как выполняется |
| --- | --- |
| Разбираем один процесс | Один, не весь бизнес. Иначе разбор растягивается на месяц |
| Показываем точки автоматизации | Где именно тратится время, с конкретными шагами |
| Оцениваем сложность | Честно: «день работы» или «месяц» |
| Предлагаем вариант решения | Архитектура словами клиента, а не схема на 40 блоков |

**Что НЕ обещаем:** точную смету, готовое техзадание, работу «в подарок».
Это прямо написано на странице — обещание без границ обходится дороже, чем его отсутствие.

## Структура страницы

| Блок | Назначение |
| --- | --- |
| Заголовок и подзаголовок | Пообещать результат разбора, не «бесплатность» |
| Что это даёт (4 пункта) | Снимает неопределённость: что я получу |
| Как это работает (3 шага) | Список → разбор → решение |
| Кому подойдёт / кому нет | Честный фильтр: спасает и клиента, и меня |
| Ограничения | Один процесс, без ТЗ, без сметы |
| Форма | Существующая `LeadForm`, источник `diagnostics` |

## Кому подойдёт

- Рутинная работа, которую делает человек, а можно поручить программе;
- заявки собираются вручную из разных мест;
- отчёты сводятся руками;
- не понятно, с чего начать автоматизацию.

## Кому НЕ подойдёт

- Нужна конкретная разработка под известное ТЗ — это сразу проект;
- нужна поддержка работающей системы — это отдельная услуга;
- нужен консультант на час по общим вопросам — не тот формат.

## Форма (правила)

Используется единая `LeadForm` (манифест `lead-form.md`) — никакой второй формы.
Источник передаётся в `?source=diagnostics&service=process-audit`, чтобы заявка в админке
была помечена как заявка на разбор, а не как обычное обращение.

Обязательные поля — те же. Дополнительных полей не добавляем:
смысл разбора в том, чтобы поговорить, а не заполнить анкету.

## SEO

- `H1`: «Бесплатный разбор бизнес-процесса» (ТЗ 11.3, группа «автоматизация»).
- `index: true` — страница полезная, содержит оффер, не дубль /services/.
- Отдельный пункт в `sitemap.xml` через общий механизм статических страниц.
- Ссылки: главная (блок услуг), `/services/`, страницы автоматизации.
- Перелинковка обратная: со страницы услуги «Автоматизация процесса» — сюда.

## Чего страница НЕ делает

- Не собирает документы (для этого личный кабинет и обычная заявка).
- Не записывает на звонок — календаря нет.
- Не обещает сроки ответа, если их неоткуда взять — на странице указан только канал связи.

## Проверка

- страница отдаёт 200 и содержит `H1` нужного вида;
- кнопка формы отправляет заявку с `source=diagnostics`;
- в админке заявка видна с этим источником;
- ссылка есть на главной и в навигации (иначе страницы никто не найдёт).
