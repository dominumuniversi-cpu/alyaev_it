# Манифест: темы (светлая / тёмная)

> Запрос владельца 26.11.2026: «Добавь переключение тёмного и светлого фона».
> Темная тема — палитра первой версии сайта (та, что была несколько часов назад), светлая — PERSONAL v2.0.

## Как устроено

```
cookie theme=light|dark
      ↓
middleware.ts  (читает cookie, кладёт заголовок x-theme)
      ↓
app/layout.tsx (className="light"|"dark" на <html>)
      ↓
globals.css    (html.dark переопределяет те же переменные)
      ↓
компоненты     (всегда только var(--c-*), никогда не «тёмный вариант класса»)
```

**Почему через cookie, а не localStorage:** страница отдаётся сервером уже в нужной теме — нет вспышки
светлой при загрузке и нет мигания при переходе между страницами.

Кнопка — `ThemeToggle` в шапке (и в мобильном меню). Переключение меняет класс на `<html>` и cookie,
**страница не перезагружается** (правило владельца: действия пользователя не перебрасывают страницу).

## Правила для новых компонентов

1. Цвет — только `var(--c-*)`. Любой сырой HEX ломает переключение темы.
2. Акцент **как текст** (подписи, номера, ссылки) — `--c-lime-ink` / `--c-terra-ink`;
   `--c-lime` и `--c-terracotta` остаются для **плашек и фонов**. Иначе на светлой бумаге получается
   светло-зелёный или светло-коралловый текст, который не читается (жалоба владельца 26.11.2026).
3. Текст **поверх** `--c-lime` — всегда `--c-lime-ink` (контраст ≥ 4,5:1 в обеих темах).
4. Секции не задают «свою палитру»: `Section surface` даёт роль `.on-dark`, которая в светлой теме —
   графит, а в тёмной — приподнятая панель (`#0B1220`).
5. Проверка правки: `tsc --noEmit` → 0, живой сайт с `?theme` не нужен — переключить кнопкой и убедиться,
   что текст читается на обоих фонах.

## Проверка

| Что | Как |
|---|---|
| Тема приходит с сервера | `curl -H 'Cookie: theme=dark' https://alyaev.ru/` → в HTML `<html class="dark"` |
| Настройка сохраняется | в cookie `theme` после клика, `max-age` 1 год |
| Нет сырых HEX в компонентах | `grep -rn '#[0-9A-Fa-f]\{6\}' frontend/src/components` → пусто |
